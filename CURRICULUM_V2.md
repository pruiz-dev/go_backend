# CURRICULUM V2: Go Backend с нуля до оффера (рынок РФ)

Этот план построен по принципу **Project-First + Offer-First**:
1. Никаких сухих упражнений в пустоту. С самого первого модуля ты развиваешь один живой проект — `subtracker` (сервис учёта подписок с аналитикой трат и уведомлениями в Telegram).
2. Каждый шаг — микродоза на 35–45 минут, после которой проект умеет делать что-то новое и это можно сразу проверить руками.
3. Учим только те 20% тем, которые закрывают 80% требований российских вакансий и собеседований (Junior / стажёр).

**Инструкция для Агента:**
- Все модули с 01 по 11 выполняются внутри единого растущего проекта `subtracker/` через короткие рабочие тикеты (2–3 тикета на модуль, по 35–45 минут каждый).
- В начале каждого модуля обновляй `subtracker/PLAN.md` списком тикетов текущего этапа.
- Модули 12–15 — это боевая подготовка к выходу на рынок (лайвкодинг, алгоритмы, симуляция тестового задания и мок-собеседования).
- В конце каждого модуля предлагай короткий `/quiz` с реальными вопросами российских собеседований по пройденной теме.

## Этап 1: Рождение `subtracker` (База Go сразу на живом проекте)
Цель: освоить синтаксис Go без скучной теории, собрав рабочую консольную версию трекера подписок.
- [ ] `01_cli_calculator` (Переменные, базовые типы, функции, `if`, `for`, `switch`, `go.mod`. Пишем первую версию `subtracker`: расчёт стоимости подписок в месяц и в год)
- [ ] `02_collections_and_stats` (Слайсы, мапы, строки и руны. Храним список подписок, группируем по категориям, считаем статистику и фильтруем расходы)
- [ ] `03_domain_model` (Структуры, указатели на практике и защита от nil-паники, методы с value/pointer receivers. Моделируем сущность `Subscription`, добавляем отмену, продление и расчёт даты следующего списания)
- [ ] `04_interfaces_errors_tests` (Интерфейсы, идиоматичная обработка ошибок, `errors.Is`/`errors.As`, `defer`, базовые юнит-тесты в `testing` и рабочий цикл Git. Разделяем бизнес-логику и хранилище через интерфейс)

## Этап 2: Выход в веб (Бэкенд-кругозор с нуля)
Цель: понять, как устроен интернет и бэкенд, и превратить консольную программу в настоящий HTTP-сервер.
- [ ] `05_http_and_rest_mvp` (Как работает веб: HTTP-запросы и ответы, методы GET/POST/PUT/DELETE, статус-коды, JSON, REST API. Поднимаем HTTP-сервер `subtracker` на стандартном `net/http` с роутингом Go 1.22+, тестируем запросы через curl/Postman)
- [ ] `06_clean_architecture` (Слоистая архитектура: handler -> service -> repository. Валидация входных данных, загрузка конфигурации из `.env`, структурированное логирование через `log/slog`)

## Этап 3: PostgreSQL и Docker (Главный фильтр на вакансиях)
Цель: освоить связку баз данных и контейнеров, без которой в РФ не берут в бэкенд.
- [ ] `07_docker_and_sql_basics` (Что такое Docker и `docker-compose`, запуск PostgreSQL в контейнере. Практический SQL: таблицы, первичные и внешние ключи, `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `JOIN`, `GROUP BY`, индексы и как они ускоряют поиск)
- [ ] `08_postgres_in_go` (Подключение из Go через `pgx`, SQL-миграции, перенос `subtracker` из памяти в PostgreSQL, транзакции и ACID на практике, аналитический эндпоинт «траты за период по категориям»)

## Этап 4: «Взрослый» бэкенд и вау-фича
Цель: закрыть две ключевые темы — безопасность пользователей и конкурентность Go на реальной задаче.
- [ ] `09_auth_and_middleware` (Регистрация и вход пользователей, хэширование паролей `bcrypt`, JWT-токены, HTTP middleware для защиты эндпоинтов — каждый пользователь видит только свои подписки)
- [ ] `10_concurrency_and_telegram_bot` (Горутины, каналы, `select`, `sync.WaitGroup`/`Mutex`, `context` с таймаутами и отменой, детектор гонок `-race`. Пишем фоновый воркер, который проверяет скорые списания и шлёт реальное уведомление в Telegram через исходящий `http.Client`, плюс graceful shutdown сервера)

## Этап 5: Упаковка уровня «Зовите на собес»
Цель: оформить проект так, чтобы техлид на GitHub сразу увидел культуру коммерческой разработки.
- [ ] `11_tests_ci_and_packaging` (Юнит-тесты бизнес-логики с моками, тестирование HTTP-хендлеров через `httptest`, линтер `golangci-lint`, `Dockerfile` + единый `docker-compose.yml` + `Makefile`, OpenAPI/Swagger-документация, GitHub Actions CI и продающий `README.md`)

## Этап 6: Мост к офферу (Рынок РФ)
Цель: научиться уверенно проходить все этапы отбора — от тестового задания до финального технического интервью.
- [ ] `12_go_interview_livecoding` (Классика российских лайвкодингов на Go: ловушки слайсов/мап/интерфейсов, паттерны Worker Pool, Merge Channels, потокобезопасный кэш с TTL и мьютексом)
- [ ] `13_algorithms_minimum` (Оценка сложности O(1), O(N), O(N log N). Базовые паттерны LeetCode Easy / простые Medium: хэш-таблицы, два указателя, скользящее окно, бинарный поиск)
- [ ] `14_test_task_simulation` (Боевая симуляция: выполняем небольшое тестовое задание в стиле Авито/Ozon с нуля за 3–5 дней строго по ТЗ — в отдельной папке, с минимумом подсказок от ментора)
- [ ] `15_resume_and_mock_interviews` (Упаковка резюме под HH.ru/Хабр Карьеру/TG-каналы, подготовка рассказа о себе и защиты архитектуры `subtracker`, отработка ответов про отсутствие опыта, серия мок-собеседований по Go, SQL, HTTP и Docker)
